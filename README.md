# คู่มือสรุปเนื้อหา ND01: สถาปัตยกรรม ESP32-S3 บอร์ด WS28P และแพลตฟอร์มเฟิร์มแวร์ FreeRTOS

เอกสารคู่มือฉบับนี้รวบรวมและสังเคราะห์เนื้อหาทั้งหมดของหลักสูตรระบบสมองกลฝังตัว ND01 ตั้งแต่ภาพรวมการเรียนรู้ สถาปัตยกรรมฮาร์ดแวร์ระดับชิป ESP32-S3 และบอร์ดทดลองหลัก **WS28P (Waveshare ESP32-S3-Touch-LCD-2.8)** เครื่องมือพัฒนา ESP-IDF ตลอดจนโครงสร้างเวิร์กช็อปเฟิร์มแวร์ robotos บนระบบปฏิบัติการเวลาจริง (FreeRTOS) เพื่อให้นักศึกษาและวิศวกรใช้เป็นคู่มืออ้างอิงทางเทคนิคในการทดลองและพัฒนาซอฟต์แวร์ฝังตัวได้อย่างเป็นระบบ

## 1. ภาพรวมหลักสูตรและแผนผังความเชื่อมโยงระบบ (System Architecture & Course Overview)

หลักสูตร ND01 มุ่งเน้นการสร้างเสริมทักษะทางวิศวกรรมระบบสมองกลฝังตัวระดับอาชีพ โดยผสานการเรียนรู้ 3 มิติหลัก ได้แก่ ความเข้าใจเชิงลึกในสถาปัตยกรรมฮาร์ดแวร์ระดับซิลิคอนและบอร์ดทดลอง (Silicon & Hardware Platform), การใช้งานชุดเครื่องมือจัดการและคอมไพล์ระดับอุตสาหกรรม (ESP-IDF Toolchain), และการออกแบบโครงสร้างซอฟต์แวร์แบบมัลติทาสก์บนระบบปฏิบัติการเวลาจริง (FreeRTOS Multi-Tasking Firmware)

การเรียนรู้เริ่มต้นในสัปดาห์เปิดตัว (Week 01) เพื่อวางทิศทางและเป้าหมายของสายงานระบบฝังตัวและอิเล็กทรอนิกส์ จากนั้นก้าวเข้าสู่การวิเคราะห์ฮาร์ดแวร์บอร์ดทดลองอย่างละเอียดในสัปดาห์ที่สอง (Week 02) ผ่าน 15 บทเรียนพื้นฐาน เข้าสู่การติดตั้งและทดสอบสภาพแวดล้อมการพัฒนาในสัปดาห์ที่สาม (Week 03) และเชื่อมโยงสู่ภาคปฏิบัติการจริงบนคลังรหัสต้นฉบับ `firmware-esp32-s3-workshop` โดยกำหนดให้บอร์ด **WS28P** เป็นบอร์ดฮาร์ดแวร์หลักของเวิร์กช็อป

### บล็อกไดอะแกรมสถาปัตยกรรมระบบ 5 ลำดับชั้น (Layered Software & Hardware Block Diagram)

โครงสร้างระบบทั้งหมดถูกจัดหมวดหมู่ออกเป็น 5 ลำดับชั้นเพื่อการออกแบบที่เป็นระบบ โดยแต่ละชั้นมีขอบเขตความรับผิดชอบที่เชื่อมโยงกันดังนี้:

| ลำดับชั้น (Layer) | องค์ประกอบระบบ (System Components) | หน้าที่และความรับผิดชอบหลัก |
| :--- | :--- | :--- |
| **Layer 5: User Application & Demos** | • `demos/demo-labs` (ex01–ex17)<br>• `labs/device-labs` (ex00–ex06)<br>• `labs/rtos-labs` (ex00–ex15)<br>• `labs/special-labs` (ex01–ex06) | โค้ดผู้ใช้เขียนแบบ Thin Application สลับรันโปรเจกต์ผ่านสคริปต์ `run NN` ซึ่งเขียนทับ `main/main.c` อัตโนมัติ |
| **Layer 4: Features & UI Widgets** | • วิดเจ็ต UI (Label, Button, Slider, Gauge, Form)<br>• การประมวลผลข้อมูล (IMU Viz, Mic Viz, Chart) | ให้บริการส่วนประกอบกราฟิกและวิดเจ็ตแสดงผลบนจอ LCD รองรับการโต้ตอบผ่านระบบสัมผัสและเซ็นเซอร์ |
| **Layer 3: Middleware & Wire Protocol** | • Prebuilt Archive `librobotos_fw.a`<br>• COBS Serial Framing บน Native USB-JTAG<br>• Message Topics, Log Streaming, Remote Param | สื่อสารระหว่างไมโครคอนโทรลเลอร์กับโฮสต์คอมพิวเตอร์ จัดการแพ็กเก็ต การแปลงรหัสข้อมูล และการกระจายข้อมูลผ่านหัวข้อ (Publish/Subscribe) |
| **Layer 2: Real-Time OS & Framework** | • FreeRTOS Kernel (Tasks, Queues, Semaphores)<br>• ESP-IDF API Drivers (SPI, I2C, RMT, SDIO)<br>• Memory Allocation (SRAM Heap, PSRAM Heap) | จัดสรรเวลาและทรัพยากรของ CPU ดูแลความปลอดภัยในการเข้าถึงหน่วยความจำ และควบคุมไดรเวอร์ฮาร์ดแวร์พื้นฐาน |
| **Layer 1: Hardware & Silicon Platform** | • ESP32-S3 Dual-Core Xtensa LX7 (S3R8)<br>• Internal SRAM 512KB + Octal PSRAM 8MB<br>• **บอร์ด Waveshare WS28P (ค่าเริ่มต้น)** / บอร์ด ES3C28P | ประมวลผลคำสั่งเชิงกายภาพ เชื่อมโยงสัญญาณบัสไฟฟ้า และขับเคลื่อนอุปกรณ์รอบข้างภายนอกทั้งหมด |

## 2. เจาะลึกฮาร์ดแวร์บอร์ด WS28P และชิป ESP32-S3 (Week 02: 15 Lessons)

เนื้อหาในสัปดาห์ที่ 2 เป็นการสำรวจทางวิศวกรรมตั้งแต่ระดับสถาปัตยกรรมภายในชิป ESP32-S3R8 จนถึงวงจรเชื่อมต่ออุปกรณ์รอบข้างบนบอร์ดทดลองหลัก **WS28P (Waveshare ESP32-S3-Touch-LCD-2.8)** รวมทั้งสิ้น 15 บทเรียน

### 2.1 บล็อกไดอะแกรมการเชื่อมต่อฮาร์ดแวร์บนบอร์ด WS28P (WS28P Hardware Interconnect Diagram)

วงจรบนบอร์ด WS28P แบ่งส่วนการสื่อสารกับชิป ESP32-S3 ออกเป็นบัสและอินเทอร์เฟซต่างๆ ตามลักษณะการทำงานของอุปกรณ์:

*   **แกนประมวลผลกลาง (Core Platform)**:
    ชิป ESP32-S3R8 (Xtensa 32-bit Dual-Core LX7 @ 240 MHz พร้อมชุดคำสั่ง Vector Instructions สำหรับงาน AI, Machine Learning และ DSP)
*   **ระบบหน่วยความจำภายในและภายนอก (Memory Architecture)**:
    เชื่อมต่อ Internal SRAM 512 KB, Embedded Octal PSRAM 8 MB ผ่าน Octal SPI Bus, และ External SPI Flash 16 MB สำหรับจัดเก็บเฟิร์มแวร์และข้อมูลกราฟิก
*   **บัสสื่อสารความเร็วสูงสำหรับจอภาพ (SPI Display Bus)**:
    เชื่อมต่อจอสี TFT LCD ขนาด 2.8 นิ้ว (ความละเอียด 240×320 พิกเซล) ผ่านบัส SPI ความเร็วสูง รองรับการส่งข้อมูลภาพผ่านฮาร์ดแวร์ DMA และการปรับความสว่าง Backlight ด้วย PWM
*   **บัสควบคุมทัชสกรีนและเซ็นเซอร์ (I2C Bus)**:
    เชื่อมต่อตัวควบคุมระบบสัมผัส Capacitive Touch โดยบอร์ด WS28P มีไดรเวอร์ฮาร์ดแวร์รองรับทั้งชิป **CST328 (Hardware V1)** และชิป **CST3530 (Hardware V2)** พร้อมทั้งควบคุมเซ็นเซอร์ตรวจวัดความเคลื่อนไหว (IMU) และชิปควบคุมระบบเสียง
*   **สายสัญญาณเสียงดิจิทัลและไมโครโฟน (Audio Chain & Microphone)**:
    เชื่อมต่อระบบถอดรหัสและขยายสัญญาณเสียง (Audio Codec & Amp) ผ่านบัส I2S ขับเสียงออกสู่ลำโพง และรับสัญญาณเสียงดิจิทัลผ่านไมโครโฟน MEMS บนบอร์ด
*   **ระบบสัญญาณพัลส์เวลาแม่นยำ (RMT Module)**:
    เชื่อมต่อหลอดไฟ WS2812B RGB LED ด้วยสายสัญญาณเดี่ยว ควบคุมความกว้างของสัญญาณระดับนาโนวินาทีผ่านโมดูลฮาร์ดแวร์ Remote Control Peripheral (RMT)
*   **ระบบบันทึกข้อมูลความเร็วสูง (MicroSD Card Slot)**:
    เชื่อมต่อช่องเสียบการ์ด MicroSD เพื่อจัดเก็บข้อมูล บันทึกประวัติการทำงาน และโหลดไฟล์ภาพกราฟิกความเร็วสูง
*   **ระบบจัดการพลังงานและการสื่อสารโฮสต์ (Power & Native USB)**:
    วงจรชาร์จแบตเตอรี่ลิเธียมพร้อมวงจรวัดระดับแรงดันแบตเตอรี่ผ่าน ADC และขั้วต่อ Native USB ตรงเข้าสู่ขา USB D+/D- ของ ESP32-S3 สำหรับการแฟลชและดีบัก

### 2.2 สรุปรายละเอียด 15 บทเรียนพื้นฐานประยุกต์บนบอร์ด WS28P

บทเรียนถูกจัดหมวดหมู่ตามลำดับการออกแบบระบบฝังตัว:

#### หมวดที่ 1: สถาปัตยกรรมชิปและหน่วยความจำ (Silicon & Architecture)

*   **บทที่ 01: ชิป ESP32-S3 บนบอร์ดทดลอง WS28P**:
    ชิปดูอัลคอร์ Xtensa LX7 ความเร็ว 240 MHz โดดเด่นด้วยชุดคำสั่ง Vector Instructions ที่ช่วยเร่งความเร็วในการคำนวณเวกเตอร์ โครงข่ายประสาทเทียมขนาดเล็ก (Edge AI) และการประมวลผลสัญญาณดิจิทัล (DSP)
*   **บทที่ 02: ประวัติ ESP32 จาก ESP8266 สู่ ESP32-S3**:
    วิวัฒนาการจากชิปโมดูล Wi-Fi สำหรับงานอดิเรก สู่ไมโครคอนโทรลเลอร์ดูอัลคอร์สมรรถนะสูงที่รวมทั้ง Wi-Fi 4 (802.11 b/g/n), Bluetooth 5 (LE) และวงจรแปลงสัญญาณขั้นสูงสำหรับอุตสาหกรรม
*   **บทที่ 03: หน่วยความจำหลายชนิดบน ESP32-S3**:
    การทำงานร่วมกันระหว่าง Internal ROM (First-stage Bootloader), Internal SRAM 512 KB (ความเร็วสูงสุด), External Octal PSRAM 8 MB (บรรจุในแพ็กเกจ SiP สำหรับ Framebuffer จอภาพ 2.8 นิ้ว และงานข้อมูลหนาแน่น), External Flash 16 MB และ eFuse สำหรับเก็บข้อมูลถาวรที่ไม่สามารถแก้ไขได้
*   **บทที่ 04: หน่วยความจำในมุมมองของเฟิร์มแวร์**:
    การแบ่งพื้นที่หน่วยความจำเป็น Heap และ Stack ภายใต้การควบคุมของ FreeRTOS, การจัดทำ Partition Table บน Flash สำหรับแยกส่วนโค้ดโปรแกรม และการใช้งาน Non-Volatile Storage (NVS) เพื่อเก็บข้อมูลการตั้งค่าระบบ
*   **บทที่ 05: ESP-IDF — Toolchain ตัวจริงของ ESP32**:
    โครงสร้างเครื่องมือคอมไพเลอร์ข้ามสถาปัตยกรรม (Cross-compiler) การทำงานของระบบ CMake, Ninja, และระบบคอนฟิกูเรชัน `menuconfig` ของ Espressif

#### หมวดที่ 2: อุปกรณ์รอบข้างและวงจรบนบอร์ด (Peripherals & Circuits)

*   **บทที่ 06: USB/Serial บนบอร์ด — ไม่มีชิป USB-UART และกับดักที่ตามมา**:
    บอร์ด WS28P ใช้ Native USB (USB Serial/JTAG) เชื่อมต่อตรงเข้าแกนประมวลผล ESP32-S3 หากโค้ดทำงานค้างจนตัดการทำงานของพอร์ต USB โฮสต์คอมพิวเตอร์จะตัดการเชื่อมต่อพอร์ต Serial ทันที ผู้ใช้จำเป็นต้องกดปุ่ม BOOT ค้างไว้แล้วกดปุ่ม RESET เพื่อบังคับเข้าสู่ฮาร์ดแวร์ดาวน์โหลดโหมด
*   **บทที่ 07: ระบบไฟและแบตเตอรี่**:
    การทำงานของวงจรชาร์จแบตเตอรี่ลิเธียม การรักษาแรงดันคงที่ 3.3V ผ่าน LDO และวงจรแบ่งแรงดัน (Voltage Divider) เพื่อส่งค่าเข้าขา ADC สำหรับวัดเปอร์เซ็นต์พลังงาน
*   **บทที่ 08: จอแสดงผลสี 2.8 นิ้ว บนบอร์ด WS28P**:
    จอ LCD TFT ขนาด 2.8 นิ้ว ความละเอียด 240×320 พิกเซล สื่อสารผ่านบัส SPI ความเร็วสูง รองรับการส่งข้อมูลเฟรมภาพด้วยฮาร์ดแวร์ DMA เพื่อไม่ให้สูญเสียรอบการทำงานของซีพียู
*   **บทที่ 09: ทัชสกรีน Capacitive (CST328 / CST3530)**:
    ตัวตรวจจับการสัมผัสแบบเก็บประจุของบอร์ด WS28P ซึ่งใช้ชิป CST328 (บนบอร์ด V1) หรือ CST3530 (บนบอร์ด V2) สื่อสารผ่านบัส I2C พร้อมสัญญาณ Interrupt แจ้งเตือนเมื่อมีการสัมผัสหน้าจอ โดยเฟิร์มแวร์มีระบบตรวจสอบฮาร์ดแวร์อัตโนมัติ
*   **บทที่ 10: ระบบเสียง — Audio Codec, Amp และ MEMS Mic**:
    สถาปัตยกรรมการประมวลผลเสียงแบบครบวงจร ทั้งการบันทึกเสียงดิจิทัลผ่านไมโครโฟน MEMS และการแปลงสัญญาณดิจิทัลเป็นเสียงแอนะล็อกผ่าน I2S เข้าสู่แอมปลิฟายเออร์ขับลำโพงสำหรับสร้างเสียงสัญญาณเตือน
*   **บทที่ 11: RGB LED WS2812B — การควบคุมความกว้างพัลส์ด้วยฮาร์ดแวร์ RMT**:
    การขับหลอดไฟอัจฉริยะที่ใช้สายสัญญาณเดี่ยวและต้องการความแม่นยำของเวลาสัญญาณระดับนาโนวินาที ซึ่งต้องใช้โมดูล Remote Control Peripheral (RMT) เพื่อป้องกันการกระตุกของสัญญาณจากมัลติทาสกิง
*   **บทที่ 12: MicroSD บนบอร์ด WS28P**:
    การเชื่อมต่อช่องอ่านการ์ดความจำด้วยความเร็วสูง ช่วยให้โหลดภาพกราฟิก วิดเจ็ต UI และบันทึกข้อมูลประวัติการทำงานได้อย่างต่อเนื่อง
*   **บทที่ 13: แผนผังขาขยาย (Expansion Header) และข้อห้ามสำคัญ**:
    การจัดระเบียบขา Pinout ทั้งบอร์ดเพื่อระบุขาที่ใช้งานได้อย่างปลอดภัย ขาที่ผูกกับวงจรภายใน และ Strapping Pins (เช่น GPIO0, GPIO45, GPIO46) ที่ห้ามมีแรงดันดึงผิดเพี้ยนตอนบูตระบบ

#### หมวดที่ 3: ความพร้อมในการพัฒนาเฟิร์มแวร์จริง (Firmware Readiness)

*   **บทที่ 14: ติดตั้ง ESP-IDF ผ่าน VS Code**:
    การติดตั้งและตั้งค่า Extension บนสภาพแวดล้อม VS Code เพื่อเชื่อมต่อการคอมไพล์ แฟลช และดีบักลงบอร์ดจริง
*   **บทที่ 15: ทบทวน Embedded C และแนวคิด FreeRTOS**:
    การทบทวนเรื่อง Pointers, Dynamic Allocation, คีย์เวิร์ด `volatile`, การจัดการบิต, โครงสร้างทาสก์ และกลไกสื่อสารข้ามทาสก์ (Queues, Semaphores)

## 3. สภาพแวดล้อมการพัฒนาและ Toolchain ESP-IDF (Week 03)

การติดตั้งสภาพแวดล้อม ESP-IDF มีเป้าหมายเพื่อให้นักศึกษาเข้าใจสถาปัตยกรรมของเครื่องมือพัฒนา และสามารถคอมไพล์โปรเจกต์พื้นฐาน (Hello World) ลงชิป ESP32-S3 บนบอร์ด WS28P ได้อย่างถูกต้อง

### 3.1 องค์ประกอบของระบบพัฒนา ESP-IDF

ระบบพัฒนาประกอบด้วย 4 ส่วนที่ทำงานร่วมกัน:

1.  **ESP-IDF Framework**: คลังไลบรารี ซอร์สโค้ด และไดรเวอร์ฮาร์ดแวร์
2.  **Compiler Toolchain**: คอมไพเลอร์เฉพาะ `xtensa-esp32s3-elf-gcc` สำหรับแปลงโค้ด C/C++
3.  **Python Virtual Environment**: สภาพแวดล้อมเสมือนของ Python ที่รวบรวมเครื่องมือจัดการระบบ เช่น `esptool.py`
4.  **Firmware Project Structure**: โครงสร้างโฟลเดอร์โปรเจกต์ที่มี `CMakeLists.txt` และโฟลเดอร์ `main/`

### 3.2 ข้อควรระวังระดับวิกฤตบน Windows และระบบอื่นๆ

> **กฎเหล็กสำหรับ Windows:** คำสั่งของ ESP-IDF ทั้งหมด (รวมถึง `export.ps1` และ `idf.py`) ต้องสั่งการผ่าน **PowerShell** เท่านั้น **ห้ามใช้ Git Bash** เป็นอันขาด เนื่องจากสภาพแวดล้อมจำลอง MSYS/MinGW ของ Git Bash จะขัดขวางและทำให้ระบบค้นหาคอมไพเลอร์ล้มเหลว

สำหรับผู้ใช้ macOS และ Linux ให้ใช้ Terminal มาตรฐาน โดยเรียกใช้สภาพแวดล้อมผ่านคำสั่ง `. ./export.sh`

### 3.3 ขั้นตอนวงจรการพัฒนาโปรเจกต์ (Development Lifecycle)

ลำดับขั้นตอนในการสร้างและทดสอบโปรเจกต์ Hello World:

*   **ขั้นตอนที่ 1: กำหนดสถาปัตยกรรมชิปเป้าหมาย (Set Target)**
    รันคำสั่ง `idf.py set-target esp32s3` เพื่อสร้างไฟล์คอนฟิกูเรชัน `sdkconfig` ให้ตรงกับฮาร์ดแวร์
*   **ขั้นตอนที่ 2: สั่งคอมไพล์โปรเจกต์ (Build)**
    รันคำสั่ง `idf.py build` เพื่อคอมไพล์ซอร์สโค้ดเป็นไฟล์ไบนารีสำหรับบูตและรัน
*   **ขั้นตอนที่ 3: แฟลชโปรแกรมลงบอร์ด (Flash)**
    รันคำสั่ง `idf.py -p COMx flash` (หรือระบุพอร์ต Serial ของแต่ละระบบปฏิบัติการ เช่น `/dev/cu.*` บน macOS หรือ `/dev/ttyACM*` บน Linux)
*   **ขั้นตอนที่ 4: เฝ้าดูผลลัพธ์ผ่านคอนโซล (Monitor)**
    รันคำสั่ง `idf.py -p COMx monitor` เพื่อเปิดหน้าต่างเทอร์มินัลรับข้อมูลจากไมโครคอนโทรลเลอร์

## 4. แพลตฟอร์มเฟิร์มแวร์ Robotos Workshop (firmware-esp32-s3-workshop)

คลังรหัสต้นฉบับ `firmware-esp32-s3-workshop` เป็นแกนกลางในการฝึกปฏิบัติการสร้างอุปกรณ์จริงและการเขียนโปรแกรมมัลติทาสก์ โดยได้รับการออกแบบให้โค้ดส่วนของผู้เรียนมีความกระชับ เรียกว่า **Thin Applications**

### 4.1 แนวคิด Thin Applications บน `librobotos_fw.a`

ในเวิร์กช็อปนี้ โค้ดที่ผู้เรียนพัฒนาจะไม่ต้องยุ่งเกี่ยวกับไดรเวอร์ระดับล่างหรือโปรโตคอลที่ซับซ้อน โดยระบบได้จัดเตรียมคลังฟังก์ชัน ไดรเวอร์อุปกรณ์ วิดเจ็ต UI และโปรโตคอลการสื่อสารทั้งหมดไว้ในไฟล์ไบนารีไลบรารี `librobotos_fw.a` (บรรจุในโฟลเดอร์ `lib/` พร้อมเฮดเดอร์ไฟล์ใน `include/`)

การสื่อสารระหว่างบอร์ดกับคอมพิวเตอร์โฮสต์ทำผ่านโปรโตคอล Wire Protocol ที่ใช้การจัดเฟรมข้อมูลแบบ COBS (Consistent Overhead Byte Stuffing) บนพอร์ต Native USB-JTAG CDC

### 4.2 บล็อกไดอะแกรมการทำงานของ CLI Switcher (`run NN`)

เวิร์กช็อปใช้โครงสร้างแบบ 1 โครงการ ESP-IDF ต่อ 1 แทร็ก เพื่อลดความซ้ำซ้อน โดยมีขั้นตอนการสลับโค้ดและการบิลด์ดังนี้:

*   **ผู้ใช้สั่งคำสั่ง**: สั่งรันคำสั่ง เช่น `.\run 01` หรือ `.\run 01 monitor`
*   **ระบบสลับโค้ด**: สคริปต์ `run` จะคัดลอกโค้ดจากแบบฝึกหัด `ex01` ไปเขียนทับไฟล์ `main/main.c` โดยอัตโนมัติ
*   **การคอมไพล์และแฟลช**: เรียกใช้เครื่องมือ `rbdev` ทำการตรวจสอบพอร์ตจากไฟล์คอนฟิก และสั่งคอมไพล์พร้อมแฟลชลงบอร์ด
*   **การแสดงผล**: หากระบุคำว่า `monitor` ระบบจะเปิดหน้าต่าง Serial Console ต่อเนื่องทันที

### 4.3 ตารางเปรียบเทียบบอร์ดฮาร์ดแวร์ที่รองรับ

| พารามิเตอร์บอร์ด | ชื่ออุปกรณ์และฮาร์ดแวร์ | ชิปจอแสดงผลและทัชสกรีน | หมายเหตุการใช้งาน |
| :--- | :--- | :--- | :--- |
| **`ws28p` (ค่าเริ่มต้นหลัก)** | Waveshare ESP32-S3-Touch-LCD-2.8 | จอ LCD สัมผัสผ่านชิป CST328 (V1) หรือ CST3530 (V2) | **บอร์ดเริ่มต้นหลักของเวิร์กช็อป** มีระบบตรวจจับฮาร์ดแวร์ V1/V2 อัตโนมัติในตัว |
| **`es3c28p`** | Ternion ESP32-S3 Board | จอ LCD ควบคุมด้วย ILI9341V พร้อมทัชสกรีน FT6336G | บอร์ดทางเลือก รองรับคำสั่งสลับใช้งานในระบบเวิร์กช็อปเดียวกัน |

### 4.4 การตั้งค่าและเริ่มใช้งานบอร์ด WS28P (Quick Start)

การใช้งานบอร์ด WS28P ทำได้โดยตั้งค่าผ่านเครื่องมือ `rb` ของเวิร์กช็อป:

*   **โคลนคลังโค้ดเวิร์กช็อป**: เข้าสู่ไดเรกทอรีโครงการ `firmware-esp32-s3-workshop`
*   **ตรวจสอบสภาพแวดล้อมและพอร์ต**: เข้าไปที่โฟลเดอร์แบบฝึกหัด เช่น `cd labs/device-labs` แล้วเรียกใช้ `.\rb doctor` (หรือ `./rb doctor` บน macOS/Linux) เพื่อตรวจสอบพอร์ต Serial
*   **บันทึกการตั้งค่าบอร์ดและพอร์ต**: รันคำสั่ง `.\rb config --port COMx --board ws28p` เพื่อกำหนดให้บอร์ด WS28P เป็นบอร์ดเป้าหมายหลัก
*   **เลือกแบบฝึกหัด คอมไพล์ และแฟลช**: รันคำสั่ง `.\run 00` สำหรับทดสอบ และ `.\run 01 monitor` เพื่อคอมไพล์ แฟลช และมอนิเตอร์ผลทันที
*   **การสั่งงานผ่าน idf.py โดยตรง**: ผู้ใช้สามารถระบุเป้าหมายบอร์ดผ่านตัวแปร CMake ได้ด้วยคำสั่ง `idf.py -DBOARD=ws28p set-target esp32s3 build flash -p COMx monitor`

## 5. แผนผังเส้นทางการทดลอง 4 แทร็กหลัก (Workshop Tracks)

เวิร์กช็อปจัดแบ่งเนื้อหาภาคปฏิบัติการออกเป็น 4 เส้นทาง (Tracks) ครอบคลุมตั้งแต่วิดเจ็ตหน้าจอไปจนถึงเกมและการใช้งานเคอร์เนลระดับสูง:

### 5.1 Track 1: Device Labs (`labs/device-labs`) — การพัฒนาอุปกรณ์ขั้นบันได

เส้นทางหลักในการฝึกสร้างอุปกรณ์สมองกลฝังตัวแบบสมบูรณ์บนบอร์ด WS28P ประกอบด้วย 7 แบบฝึกหัด:

*   **`ex00 Hello`**: การเริ่มต้นระบบและการแสดงผลข้อความสถานะ
*   **`ex01 Spirit`**: เครื่องวัดระดับน้ำดิจิทัล (Digital Spirit Level) ใช้เซ็นเซอร์วัดความเอียง IMU
*   **`ex02 Alarm`**: ระบบตั้งเวลาพร้อมส่งสัญญาณเตือนผ่านระบบเสียง
*   **`ex03 React`**: เกมทดสอบความเร็วในการตอบสนองร่วมกับระบบสัมผัส
*   **`ex04 Metro`**: เครื่องเคาะจังหวะดนตรี (Metronome) ควบคุมความแม่นยำด้วย FreeRTOS
*   **`ex05 Scope`**: ออสซิลโลสโคปขนาดเล็ก รับสัญญาณแอนะล็อกและวาดกราฟลงจอภาพ
*   **`ex06 Monitor`**: ระบบเฝ้าตรวจวัดและแสดงผลสถานะอุปกรณ์แบบรวมศูนย์

### 5.2 Track 2: RTOS Labs (`labs/rtos-labs`) — FreeRTOS เชิงลึกและ Capstone

เจาะลึกกลไกภายในของระบบปฏิบัติการเวลาจริง (แบบฝึกหัด `ex00` ถึง `ex15`):

*   **การกำหนดแกนประมวลผล (Core Affinity)**: การบังคับให้ทาสก์ทำงานเฉพาะบน Core 0 หรือ Core 1
*   **การนับรอบเวลาของระบบ (`ex02-os-tick`)**: การวิเคราะห์ความถี่ของ OS Tick และต้นทุนเวลาในการสลับบริบท (Context Switch)
*   **การประสานเวลาและส่งข้อมูล (Queues & Sync)**: การใช้งาน Message Queue และ Semaphore เพื่อถ่ายโอนข้อมูลข้ามทาสก์อย่างปลอดภัย
*   **ตัวตั้งเวลาและการบริการขัดจังหวะ (Timers & ISR)**: การเขียนฟังก์ชันขัดจังหวะและการสื่อสารกับทาสก์ผ่าน FromISR API
*   **มินิเกมประยุกต์ใช้งานจริง (IMU Games Capstone)**: การพัฒนาเกมควบคุมวัตถุบนหน้าจอด้วยการเอียงบอร์ด โดยผสานข้อมูลเซ็นเซอร์ IMU เข้ากับการเรนเดอร์ภาพแบบเรียลไทม์

### 5.3 Track 3: Special Labs (`labs/special-labs`) — กลไกเฉพาะทางของ FreeRTOS

เส้นทางเสริมสำหรับศึกษาฟังก์ชันระดับสูงของ FreeRTOS (แบบฝึกหัด `ex01` ถึง `ex06`):

*   **Mutex**: การปกป้องพื้นที่วิกฤต (Critical Section) และการป้องกันปัญหา Priority Inversion
*   **BOOT ISR**: การจับสัญญาณกดปุ่ม BOOT เพื่อสร้างฮาร์ดแวร์อินเทอร์รัพต์
*   **Priority Management**: การทดสอบพฤติกรรมการแย่งชิงเวลาซีพียูตามระดับความสำคัญ
*   **Counting Semaphore**: การจำกัดและควบคุมโควตาการเข้าถึงทรัพยากร
*   **Event Groups**: การรอคอยเงื่อนไขหลายอย่างพร้อมกันก่อนอนุญาตให้ทาสก์ทำงาน
*   **Reload Timer**: การตั้งเวลาซอฟต์แวร์แบบเรียกซ้ำอัตโนมัติ

### 5.4 Track 4: Demo Labs (`demos/demo-labs`) — แคตตาล็อก UI Components และ Wire

แคตตาล็อกรวมตัวอย่างการสร้างอินเทอร์เฟซผู้ใช้และระบบสื่อสาร 17 แบบฝึกหัด:

*   **กลุ่มวิดเจ็ตแสดงผลและอินพุต (ex01–ex09)**:
    *   `ex01-label`: การจัดวางข้อความแบบตาราง 4×4 ด้วย `rb_label`, `rb_screen` และ `rb_layout`
    *   `ex02-led`: แผงหลอดไฟเสมือน 4×4 `rb_led` พร้อมการกระพริบแบบ Breathe
    *   `ex03-term`: หน้าต่างเทอร์มินัล 3×2 `rb_term` รองรับการพิมพ์ข้อความพร้อมกันจาก 6 ทาสก์
    *   `ex04-switch` & `ex05-button`: สวิตช์และปุ่มกดหลากหลายรูปแบบ ทั้งแบบกดติดปล่อยดับและแบบ Toggle
    *   `ex06-slider`, `ex07-checkbox`, `ex08-radio`: สไลเดอร์ปรับค่า เช็คบ็อกซ์ และตัวเลือกแบบเอกเทศ
    *   `ex09-form`: การสร้างหน้าฟอร์มรวมวิดเจ็ตทุกชนิดทำงานประสานกัน
*   **กลุ่มการเชื่อมต่อเครือข่ายและการแสดงผลขั้นสูง (ex10–ex17)**:
    *   `ex10-log`: การส่งข้อมูล Log สู่โฮสต์ผ่าน Wire Protocol ด้วย `rb_node`, `rb_log` และ Topic Publish
    *   `ex11-gauge` & `ex14-progress`: เกจวัดวงกลมและแถบแสดงความคืบหน้า
    *   `ex12-param`: ตารางพารามิเตอร์ `rb_param_*` ที่ปรับแต่งได้ทั้งจากบอร์ดและคำสั่งจากโฮสต์
    *   `ex13-topics-ui`: การเชื่อมต่อสไลเดอร์หน้าจอเข้ากับเกจวัดและส่งข้อมูลผ่าน `rb_publish`
    *   `ex15-chart`: กราฟแสดงผลแบบเรียลไทม์รองรับโหมดเลื่อน (Scroll) และโหมดย้อนหลัง (History)
    *   `ex16-imu-viz` & `ex17-mic-viz`: ระบบแสดงผลความเอียงและระดับความดังของเสียงไมโครโฟนแบบ dBFS

## 6. คู่มือการตรวจวินิจฉัยและแก้ไขปัญหาทางเทคนิค (Classroom Troubleshooting Playbook)

ตารางสรุปปัญหาที่พบบ่อยในการปฏิบัติการในห้องเรียน สาเหตุ และวิธีแก้ไข:

| ปัญหาที่พบ (Symptom) | สาเหตุที่แท้จริง (Root Cause) | วิธีการแก้ไขปัญหา (Remediation) |
| :--- | :--- | :--- |
| **สคริปต์ `.ps1` ถูกบล็อกบน Windows** | Execution Policy ของ PowerShell ไม่อนุญาตให้รันสคริปต์ที่ยังไม่ได้ลงนาม | รันคำสั่ง `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` ในหน้าต่าง PowerShell นั้นๆ |
| **แจ้งเตือนข้อผิดพลาด `No module named 'rich_click'` หรือ `click`** | สภาพแวดล้อม Python venv ของ ESP-IDF ยังติดตั้งแพ็กเกจไม่สมบูรณ์ | รัน `install.bat` และ `export.ps1` จากโฟลเดอร์ ESP-IDF เพื่อซ่อมแซมแพ็กเกจ จากนั้นตรวจสอบด้วย `rb doctor` |
| **macOS Gatekeeper บล็อกการรัน `rbdev`** | ระบบความปลอดภัยของ macOS กักกันโปรแกรมไบนารีที่ดาวน์โหลดจากภายนอก | คลิกขวาที่ไฟล์ `rbdev/mac/rbdev` ใน Finder แล้วเลือก "Open" หนึ่งครั้งเพื่อยืนยันการอนุญาต |
| **Linux: สิทธิ์การเข้าถึงพอร์ตถูกปฏิเสธ (Permission denied บน `/dev/tty*`)** | ผู้ใช้ยังไม่ได้ถูกเพิ่มเข้าไปในกลุ่มผู้ใช้งานฮาร์ดแวร์ Serial | รันคำสั่ง `sudo usermod -aG dialout $USER` จากนั้นออกจากระบบแล้วล็อกอินใหม่ |
| **พอร์ต Serial หายไปหลังจากการแฟลช** | โค้ดของเฟิร์มแวร์ค้างหรือปิดการทำงานของ Native USB CDC ทำให้คอมพิวเตอร์ตัดการเชื่อมต่อพอร์ต | กดปุ่ม **BOOT** บนบอร์ดค้างไว้ แล้วกดปุ่ม **RESET** หนึ่งครั้ง จากนั้นปล่อยปุ่ม BOOT เพื่อเข้าสู่ Download Mode ด้วยฮาร์ดแวร์ แล้วจึงสั่งแฟลชใหม่ |
| **เปลี่ยนบอร์ดแล้วคอมไพล์ไม่ผ่าน** | ข้อมูลการตั้งค่าบอร์ดเดิมยังคงค้างอยู่ในโฟลเดอร์ Build | รันคำสั่ง `.\rb reconfigure` หรือลบโฟลเดอร์ `build/` ออกเพื่อทำการคอมไพล์ใหม่ทั้งหมด (Clean Build) |
